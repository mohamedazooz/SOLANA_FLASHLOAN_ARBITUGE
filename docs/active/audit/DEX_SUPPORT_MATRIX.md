## Support classification legend

Pillar coverage per protocol:
**A** Discovery · **B** Account decoding · **C** Quote (exact-in/out) · **D** Sizing · **E** Instruction building · **F** CPI/exec support (editor program) · **G** Simulation support · **H** Mainnet verification (snapshot or SDK differential).

Full support = **A+B+C+D+E+G+F+H**. Anything less is classified by its actual source path below. Generic family-level CPMM/CLMM fallbacks are prohibited; a venue without a protocol-specific, verified state model is quote-only or unsupported.

## Key findings

- **DEX-F-2026-11-22-N1 (P1 ? safety gate applied, venues remain unsupported):** the current `UniversalQuoteDispatcher` rejects incomplete protocol states; legacy route-graph adapters are explicit `QuoteOnlyAdapter`s and execution capability rejects DAMM v2, DBC, and LaunchLab. Meteora DLMM Pro has been removed from the active enum/runtime. Direct DAMM v2 / DBC adapters refuse quotes; the DAMM parser names offset 296..328 `whitelisted_vault` (not a swap config). LaunchLab retains a fee-config verification gate and rejects Token-2022 until dynamic TransferHook account resolution and instruction/account parity exist. Re-enable only after protocol-native state hydration, fees, sizing semantics, account graph, differential tests, and simulation are complete.
- **DEX-F-2026-11-25-N2 (P1, partially addressed 2026-11-27):** Discovery catalog `fee_bps` is not authoritative. Hydration now batches the full PoolState, AmmConfig, both vaults, ObservationState, both SPL mints, optional TickArrayBitmapExtension, and bitmap-selected TickArrayState accounts in one RPC context; validates program ownership, Anchor discriminators, full account lengths, canonical pool/vault/observation PDAs and bumps, pool-owned initialized vaults, mint ownership/decimals, config tick spacing, mint/vault pairing, tick-array start/count, default/extension bitmap membership, and current TickState padding semantics; and uses the live `AmmConfig.trade_fee_rate` plus a conservative maximum-volatility dynamic-fee bound. The selector caps coverage at three arrays per direction. Pools with non-input fee modes, extension-bearing assets, invalid/short accounts, or missing selected arrays remain excluded. The resulting CLMM state is quote-only: the engine retains an unknown-impact sentinel and the production risk gate prevents dispatch; no live execution is enabled. Official sources: `raydium-clmm/programs/amm/src/states/{config,pool,tick_array,oracle}.rs` and `raydium-docs-v1/products/clmm/math.mdx`.
- **Raydium AMM v4:** V4 support is preserved. AmmInfo, both vaults and Clock are re-read in one coherent RPC context; owner, vault mint/authority/state, status and WaitingTrade open-time checks gate promotion. Exact swap-fee numerator/denominator are retained, and curve reserves subtract `need_take_pnl_coin/pc` from raw vault balances. Broader real-pool SDK parity across both directions and multiple input sizes remains outstanding.
- **Transfer-fee extension assets:** coherent epoch-aware `TransferFeeConfig` is supported in quote-only paths; transaction construction remains fail-closed. The static `ExtraAccountMetaList` parser now preserves signer/writable flags and rejects malformed flags, but dynamic-seed/PDA account resolution and full instruction/account parity are still not implemented. Keep extension-bearing assets out of live execution.
- **Jupiter:** v6 quote/compile client exists (`arb-tx/src/protocols/jupiter.rs`) for envelope/relay paths; **no protocol math or execution beyond assembly** — it is a transport aid, NOT a supported execution venue; no discovery arm.
- **Pump.fun graduation boundary:** bonding-curve→PumpSwap transitions covered by separate engine + boundary tests; no linear approximations anywhere in the *supported* set.
