## 2. أدوات القياس الموجودة

### `latency_bench`

برنامج مستقل يقيس:
1. جلب الحسابات الحقيقية من RPC.
2. فكّ الترميز (Raydium/Orca).
3. `arb-math` (sizing + split).
4. توقيع Ed25519 + ALT packing + blockhash حقيقي.
5. زمن Jito relay.
6. الميزانية الكلية مقابل 400 ms (slot deadline).

**لم يتم تشغيله في هذه المهمة** لأنه:
- يتطلب `.env` بمفاتيح RPC حقيقية،
- ينشئ ويوقّع معاملة بمفتاح حقيقي (حتى لو لم يُرسل)،
- سياسة المهمة تمنع أي تعامل مع مفاتيح/معاملات حقيقية.

**الحالة:** ⚠️ **not executed** (موجود، غير مُتحقَّق في هذه البيئة).

### `health_monitor`

- `record_latency(latency_ms)` يسجّل تنبيهات عند تجاوز 1,000 ms أو تعافٍ لاحق.
- **لا يوجد حاجز (gate) يمنع التنفيذ عند بطء خط الأنابيب** — التنبيه فقط. هذا يعني أن تأخّراً في ingest قد يصل إلى منافسة على slot قديم دون رفض صريح. يعتمد الرفض على freshness (`max_age_slots`) وليس على زمن المعالجة.

**التصنيف:** P2 — لا يوجد budget enforcement صريح لزمن ما قبل الإرسال.

## 3. تحليل نظري لميزانية الزمن

| المرحلة | تقدير | ملاحظة |
|---|---|---|
| استقبال account update (gRPC) | 1–15 ms | يعتمد على المزوّد والموقع |
| فكّ الترميز + quote | < 1 ms | حسابات صحيحة، لا I/O |
| route search / sizing | < 1 ms | `arb-math` (بدون تخصيص ثقيل) |
| بناء V1 + ALT | < 1 ms | ترميز بايتات فقط |
| توقيع Ed25519 | ~0.1 ms | عملية واحدة |
| إرسال إلى leader | 5–50 ms | شبكة |

هذه **تقديرات معمارية**، وليست قياسات. لا توجد قياسات محلية موثوقة في هذه الجلسة.

## 4. عيوب/مخاطر مرصودة

1. **`latency_bench` يحتوي عناوين vault مضمّنة** (مثل `HLmqeL62...`, `EUuUbDc...`) بدلاً من قراءتها من حساب البول. إذا تغيّرت الخزائن أو كان البول مختلفاً، سيقيس المسار الخطأ.
   - **التصنيف:** P2.
2. **لا يوجد CI benchmark** يمنع الانحدار في زمن الترميز.
   - **التصنيف:** P2.
3. **`133 ms` ليس زمن هبوط**: لا يوجد قياس `confirmed` latency في الدليل.
   - **التصنيف:** P1 لتقرير الأداء (يجب عدم استخدامه كدليل سرعة تنفيذ).
