On Polymarket that means the on-chain <code>order_filled_v3</code> tape — settled on Ethereum, so it is <strong>complete by construction</strong>: there is no market-data feed to drop or miss, every trade is there with price, size, wallet and timestamp.</p><p><strong>One honest methodology note.</strong> HIP-4’s fills are bursty — the median gap between trades is ~1s but the 90th percentile is ~2 minutes and the worst is ~1.7 hours. A “last traded price” would go stale for long stretches, so for HIP-4’s <em>continuous</em> price we use its <strong>L2 book mid</strong> (7,250 updates, always fresh). Polymarket’s fills are dense enough (90th-percentile gap ~27s) to carry its price directly. So the basis below is <strong>Polymarket’s last trade minus HIP-4’s book mid</strong> — each venue’s best available price signal. That mixes a trade against a mid, so a slice of the raw basis is just half-spread microstructure, not pure mispricing; the order-book capture (end of post) is what tightens that.</p><p><strong>Mapping.</strong> HIP-4 exposes the decision as events <code>510</code>/<code>511</code>/<code>512</code>, each a Yes/No pair <code>#&lt;event&gt;&lt;side&gt;</code> (<code>0=Yes</code>,<code>1=No</code>). By nearest live mid: <code>510 → No change</code>, <code>511 → 50+ bps increase</code>, <code>512 → 25 bps increase</code>. Nothing depends on a websocket staying up, which is exactly the property you want when a single event can move millions in a minute.</p><p>We <em>also</em> run a full Polymarket order-book capture (snapshots + quote deltas).
