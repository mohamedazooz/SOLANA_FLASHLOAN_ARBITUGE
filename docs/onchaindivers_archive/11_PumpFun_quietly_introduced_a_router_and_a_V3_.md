V2 already supported them. The change is how PumpFun’s own router connects a user’s input asset to those curves.</p><p>A typical V3 route is:</p><div class="highlighted_code_block" data-attrs="{&quot;language&quot;:&quot;plaintext&quot;,&quot;nodeId&quot;:null}" data-component-name="HighlightedCodeBlockToDOM"><pre class="shiki"><code class="language-plaintext">SOL

  ↓

quote token

  ↓

PumpFun token-quoted bonding curve</code></pre></div><p>In one mainnet transaction, the PumpFun router sent SOL through Jupiter, received a non-standard quote token, and passed the routed amount into `buy_exact_quote_in_v3`. The user received the bonding-curve token without retaining the intermediate quote asset.</p><h4>How this differs from V2: the SPX example</h4><p>V2 could already trade a bonding curve quoted in SPX. A transaction we inspected on October 3 used the following construction:</p><div class="highlighted_code_block" data-attrs="{&quot;language&quot;:&quot;plaintext&quot;,&quot;nodeId&quot;:null}" data-component-name="HighlightedCodeBlockToDOM"><pre class="shiki"><code class="language-plaintext">Top-level Jupiter instruction: SOL → SPX

User’s SPX token account: receives the routed SPX

Top-level Pump instruction: BuyExactQuoteInV2 spends SPX

User’s token account: receives the PumpFun token</code></pre></div><p>The route was atomic, but the client had to compose Jupiter and Pump as separate top-level instructions. The user’s associated token account acted as the handoff between the two programs, and the Pump instruction carried a fixed quote-token budget prepared before execution.</p><p>In the inspected transaction, Jupiter delivered `277.38145186 SPX`. `BuyExactQuoteInV2` then spent `274.60763782 SPX`, including fee transfers, leaving `2.77381404 SPX` in the user’s account. That remainder is evidence of the prebuilt two-step route, not a protocol failure.</p><p>The inspected V3 route had a different shape:</p><div class="highlighted_code_block" data-attrs="{&quot;language&quot;:&quot;plaintext&quot;,&quot;nodeId&quot;:null}" data-component-name="HighlightedCodeBlockToDOM"><pre class="shiki"><code class="language-plaintext">Top-level PumpFun router instruction
  ├─ CPI to Jupiter: SOL → route assets → quote token
  └─ CPI to Pump: BuyExactQuoteInV3</code></pre></div><p>The router handled the quote token inside its own call. Jupiter produced `497.904744` units of the target quote token; V3 consumed the same `497.904744` units across the curve purchase and fee transfers. The user received the base token and did not finish with quote-token dust.</p><div class="highlighted_code_block" data-attrs="{&quot;language&quot;:&quot;markdown&quot;,&quot;nodeId&quot;:null}" data-component-name="HighlightedCodeBlockToDOM"><pre class="shiki"><code class="language-markdown">| | V2 with SPX | V3 routed flow |
|---|---|---|
| Non-standard quote tokens | Already supported | Still supported |
| Route construction | Client composes separate Jupiter and Pump instructions | One PumpFun router instruction performs both legs through CPI |
| Intermediate quote account | User’s quote-token account | Managed within the router flow |
| Amount passed to Pump | Fixed in a separate top-level Pump instruction | The CPI amount exactly matched the routed quote-token output in the inspected trade |
| Observed remainder | `2.77381404 SPX` in the inspected trade | No quote-token remainder for the user in the inspected trade |</code></pre></div><p>So the public-facing change is **integration, not first-time SPX support**. V2 proved that SPX-quoted curves already worked. V3 makes the same class of trade native to PumpFun’s router and easier to execute from SOL across more quote assets.</p><p>This distinction also changes how the first adoption numbers should be read. V3 buys used 55 quote mints in our initial sample. The older V2 buys routed by this specific PumpFun program used only SOL and USDC, but V2 activity across direct calls, Jupiter, and third-party routers already included SPX and other non-standard quotes.</p><p>We did not observe an SPX-denominated V3 buy in the reviewed window, so SPX is the verified V2 comparison—not evidence that every older quote mint had already moved to V3.</p><p>Verification transactions:</p><p>- V2 SPX route: [`3FzWcn...pmhp`](https://explorer.solana.com/tx/3FzWcnDQTFK5rhTJvwwhhm99pB6oJB6ZYrATEEUEGNztTzvGpkJPNQQkLbLFNvPi62TC3giRY9tL33DwxtX5pmhp)</p><p>- V3 routed buy: [`55C1rB...kZ2Y`](https://explorer.solana.com/tx/55C1rB8uhHQDD2ToiHwL7KLLYr2m8tWmAmLjP3UncxRcBG5td2JwcKZM1oq9zz4jiDthdmrKxMCPbsuDMLqkkZ2Y)</p><p>We have added `buy_exact_quote_in_v3` to `pumpfun_v2_swaps`:</p><p>| Field | Value |</p><p>|---|---|</p><p>| Discriminator | `e1f7501ed5b38488` |</p><p>| Account layout | 17 accounts |</p><p>| Base mint | `accounts[1]` |</p><p>| Quote mint | `accounts[2]` |</p><p>| User | `accounts[8]` |</p><p>| Trade mode | Exact quote input |</p><p>| Display label | `BEQ3` |</p><p>The rows use the existing schema. The `parent_program` field identifies routed traffic.</p><p>## Other updates in the same deployment</p><p>The upgraded binaries contain several methods that were not present in the public IDLs.</p><p>### New bonding-curve methods</p><p>```text</p><p>buy_exact_quote_in_v3</p><p>sell_v3</p><p>buy_v3</p><p>```</p><p>### New PumpSwap methods</p><p>```text</p><p>buy_exact_quote_in_v2</p><p>sell_v2</p><p>buy_v2</p><p>```</p><p>The PumpSwap names match the quote-token-aware V2 interface already used by the bonding curve.</p><p>### Quote-mint-aware fee lookup</p><p>PumpSwap now calls `get_fees_with_quote_mint` on `pump_fees` during nearly every swap. In a fixed 200-block scan we found:</p><p>```text</p><p>get_fees_with_quote_mint: 20,835 calls</p><p>old get_fees:                  6 calls</p><p>```</p><p>The fee tier is returned as program return data rather than a trade event. This allows fee selection to depend on the quote mint instead of assuming a SOL-denominated pool.</p><p>### Fee collection methods</p><p>Both `pump` and `pump_amm` now contain:</p><p>```text</p><p>sweep_protocol_fee</p><p>sweep_creator_fee</p><p>```</p><p>The bonding-curve versions were already running as top-level mainnet transactions during our review. `pump_fees` also gained the admin methods `set_exotic_flat_fees` and `admin_cto_sharing_config`.</p><p>## The program using the new routes</p><p>Most early V3 activity came through:</p><p>```text</p><p>6Vo3245eszAb5wuqEMw8mGdbfRUdKbHhDHP5LcaGuTAB</p><p>```</p><p>This is a PumpFun-owned routing program. Its upgrade authority is:</p><p>```text</p><p>7gZufwwAo17y5kg8FMyJy2phgpvv9RSdzWtdXiWHjFr8</p><p>```</p><p>The same authority controls all three upgraded PumpFun programs:</p><p>| Program | Address |</p><p>|---|---|</p><p>| `pump` | `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P` |</p><p>| `pump_amm` | `pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA` |</p><p>| `pump_fees` | `pfeeUxB6jkeY1Hxd7CsFCAjcbHA9rWtchMGdZ6VojVZ` |</p><p>The shared authority and deployment timing show that the router and the new methods shipped together.</p><p>The router can interact with:</p><p>- PumpFun bonding curves and PumpSwap;</p><p>- Jupiter;</p><p>- Raydium AMM, CLMM, CPMM, and LaunchLab;</p><p>- Meteora DAMM, DBC, and DLMM;</p><p>- limit-order creation, execution, and cancellation.</p><p>In a sample of 120 router transactions, its most common calls were:</p><p>| Router method | Transactions |</p><p>|---|---:|</p><p>| `BondingCurveV3` | 49 |</p><p>| `PumpSwapV3` | 44 |</p><p>| `SellBondingCurvePercentage` | 14 |</p><p>| `SellPumpSwapPercentage` | 7 |</p><p>A small amount of V3 traffic later appeared outside the primary router, indicating that other integrations had started to adopt the new methods.</p><p>## What changed for the data</p><p>PumpFun’s October 2 deployment changed more than one instruction:</p><p>- PumpFun’s own router can now reach token-quoted bonding curves through a wider set of input routes;</p><p>- PumpSwap received matching quote-token-aware methods;</p><p>- fee calculation now accepts the quote mint;</p><p>- a PumpFun-owned router connects these methods to several Solana venues;</p><p>- the changes were live on-chain before they appeared in the public IDLs.</p><p>The first supported V3 route is now indexed without a schema change.
