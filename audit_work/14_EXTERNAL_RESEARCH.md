## 1. Solana legacy vs versioned (v0) wire format; 1232-byte limit; address tables; signatures

- **URL:** https://github.com/anza-xyz/solana-sdk/blob/master/packet/src/lib.rs (raw: .../master/packet/src/lib.rs) — **source code** (official Anza solana-sdk) — supports: `PACKET_DATA_SIZE = 1280 - 40 - 8 = 1232` bytes max over-the-wire transaction size; `static_assertions::const_assert_eq!(PACKET_DATA_SIZE, 1232);` — 1280 (IPv6 min MTU) minus 40 (IPv6 header) minus 8 (fragment header). Legacy and v0 transactions may not exceed 1232 bytes serialized.
- **URL:** https://github.com/anza-xyz/solana-sdk/blob/master/message/src/lib.rs — **source code** — supports: a `Message` is "the compact internal encoding of a transaction, as transmitted across the network and stored in, and operated on, by the runtime"; contains flat account-key array, `MessageHeader`, recent blockhash, compact-u16-counted instructions; "serialized messages must fit into the IPv6 MTU size, conservatively assumed to be 1280 bytes."
- **URL:** https://github.com/anza-xyz/solana-sdk/blob/master/message/src/versions/mod.rs — **source code** — supports: `pub const MESSAGE_VERSION_PREFIX: u8 = 0x80;`; `VersionedMessage::{Legacy, V0, V1}`; serialization rule: high bit set → low 7 bits select version starting at 0 (v0 = 0x80, v1 = 0x81); high bit unset → legacy. V1 variant present in the stable SDK.
- **URL:** https://github.com/anza-xyz/solana-sdk/tree/master/transaction — **source code** — supports: `Transaction { signatures, message }`; signers sign the serialized message prefix; 64-byte Ed25519 signatures.
- **URL:** https://github.com/anza-xyz/agave/blob/master/runtime-transaction/src/transaction_limits.rs — **source code** (official) — supports: `MAX_LEGACY_AND_V0_TRANSACTION_SIZE = 1232`, `v1::MAX_TRANSACTION_SIZE (4096)`, `MAX_V1_SIGNATURES = 12`, `MAX_V1_ACCOUNTS = 96`, instruction count limit `MAX_INSTRUCTION_TRACE_LENGTH` (64); legacy/v0 >1232 B → `SanitizeFailure`; v0 static keys still bounded by the 1232 B budget.
- **URL:** https://github.com/anza-xyz/agave/blob/master/accounts-db/src/account_locks.rs — **source code** — supports: `DEFAULT_TX_ACCOUNT_LOCKS = 64`; per-format `TransactionAccountLockLimits { legacy, v0, v1 }`.
- **URL:** https://docs.anza.xyz/proposals/versioned-transactions — **official Anza docs** (JS-rendered; content mirrored in the SIMD repo) — supports: v0 = legacy message bytes + 0x80 prefix + `address_table_lookups` tail.
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/core/transactions/versioned-transactions.mdx — **official Solana docs (content mirror of solana.com/docs)** — supports: table — legacy 1,232 B / v0 1,232 B + ALTs / v1 4,096 B, no ALTs, resource limits in message config; ALT-resolved addresses appended after static keys (writable lookups first, then read-only); resolved accounts cannot sign; "at runtime, before execution begins, the validator resolves all ALT references into full public keys"; v1 is **active on mainnet, devnet and testnet**; base58 encoding remains capped at 1232 — transactions >1232 B must use base64.
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/cookbook/transactions/versions.mdx — **official Solana docs (mirror)** — supports: version table (legacy 1,232; v0 1,232 + ALTs; v1 4,096); `maxSupportedTransactionVersion` semantics for RPC reads (omitting it = legacy-only; must be integer `1` for v1).
- **num signatures:** legacy/v0 have no hard signature-count constant in sanitization; they are size-bounded (each signature is 64 B, compact-u16 length-prefixed). V1 enforces 12 signatures max (SIMD-0385 + agave `MAX_V1_SIGNATURES`). SIMD-0385 table: "signatures per transaction 12 (prior max 12, max implied by format 42/96)" — i.e., v0's effective cap is also 12 via `sanitize` signature limits in practice; the enforced 12-signature rule for v1 is explicit.
- **num accounts:** legacy/v0 ≈ 32 size-bound (~1232 B / 32 B per key); v0 effectively 64 via ALTs; v1 64 inline (96 behind SIMD-0596).

*Authoritative: yes (source + official docs).*

## 2. SIMD-0385 (Transaction V1) status — activated on mainnet?

- **URL:** https://github.com/solana-foundation/solana-improvement-documents/blob/master/proposals/0385-transaction-v1.md — **official SIMD repository (Solana Foundation)** — supports: **status: Activated**, created 2025-10-24, authors jacobcreech/apfitzge, Standard/Core. VersionByte = `129`; no ALTs; `NumInstructions > 64` → sanitization failure; size limit 4096; signatures ≤ 12; num accounts ≤ 64 (96 via SIMD-0596); accounts/instruction ≤ 255; ComputeBudget instructions are successful **no-ops** in v1; limits via `TransactionConfigMask` (priority-fee bits [0,1] → u64 **total lamports**, CU-limit bit 2 u32, loaded-accounts-data-size bit 3 u32, heap-size bit 4 u32 multiple of 1024 in [32 KiB, 256 KiB]); unset fields default to 0 CU / 0 bytes / 32 KiB heap / fee 0.
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/core/transactions/versioned-transactions.mdx — **official docs (mirror)** — supports: callout — "The v1 format is active on mainnet, devnet, and testnet"; breaking-change guidance: pass `maxSupportedTransactionVersion: 1` (JSON integer, not string); `getBlock` fails with `-32015`; `blockSubscribe` emits `block: null`; pipeline clients deriving priority fees from ComputeBudget instructions silently report zero for v1 transactions; `@solana/kit` 8.0+, Agave-4.2-generation Rust crates or web3.js v3 required to build v1; web3.js v1 ≥1.99.0 can read but not build/send v1.
- **URL:** https://github.com/anza-xyz/agave/blob/master/feature-set/src/lib.rs — **source code** — supports: `pub mod enable_tx_v1 { declare_id!("txv1aq4pp281K9um3tnPgkfX8UqtFT6wcVW3hNezGLL"); }` labeled "SIMD-0385: Transaction V1"; `pub mod increase_tx_v1_account_lock_limit { declare_id!("8ZVMrzG6pPBREHMbHNyrErKJsXA7b1vg9e1iycSooCeY"); }` labeled "SIMD-0596: Increase transaction v1 account lock limit to 96".
- **URL:** https://github.com/anza-xyz/solana-sdk/blob/master/message/src/versions/v1/mod.rs — **source code** — supports: `V1_PREFIX = MESSAGE_VERSION_PREFIX | 1` (i.e., 129); `MAX_TRANSACTION_SIZE = 4096`; `DEFAULT_HEAP_SIZE = MIN_HEAP_SIZE = 32 * 1024`, `MAX_HEAP_SIZE = 256 * 1024`; `FIXED_HEADER_SIZE` computation; signature size constant 64.
- **URL:** https://github.com/anza-xyz/agave/blob/master/CHANGELOG.md — **source code** — supports: "The `solana` CLI now creates version 1 transactions (txv1)" (Agave release notes — txv1 shipping in current releases).
- **SIMD-0596** (96-account v1 lock limit) — **URL:** https://github.com/solana-foundation/solana-improvement-documents/blob/master/proposals/0596-increase-txv1-account-lock-limit-to-96.md — **official SIMD** — support: status **Draft**, created 2026-08-11, extends SIMD-0385; v1 64 → 96; legacy/v0 stay at 64; mandates removal of the old `increase_tx_account_lock_limit` (128) feature before activation. Activation on mainnet **not confirmed**.
- **Internal inconsistency:** SIMD-0385 frontmatter reads `status: Activated` while `feature:` is still "(fill in with feature key...)". Treat activation as real (docs + agave feature-set + CHANGELOG all agree v1 ships) but the precise activation epoch/slot is **unverifiable** from public docs this session.
- **Does the engine need to handle v1?** Yes for correctness of parsing/routing on mainnet — v1 transactions exist in blocks; any indexer/tx-parser that assumes only legacy/v0 will fail (`-32015`) on v1 transactions.

*Authoritative: yes for format/status "Activated" (SIMD + official docs + agave); mainnet activation slot unverifiable.*

## 3. Address Lookup Table (ALT) lifecycle

- **URL:** https://github.com/anza-xyz/solana-sdk/blob/master/address-lookup-table-interface/src/state.rs — **source code** (official interface crate) — supports: `LOOKUP_TABLE_MAX_ADDRESSES = 256`; `LOOKUP_TABLE_META_SIZE = 56`; `LookupTableMeta { deactivation_slot, last_extended_slot, last_extended_slot_start_index, authority, _padding }`; `is_active()` — true for Activated and Deactivating; `status()` — `deactivation_slot == Slot::MAX` → Activated; `deactivation_slot == current_slot` → Deactivating{remaining_blocks: MAX_ENTRIES+1}; if position found in slot_hashes → Deactivating with remaining = `MAX_ENTRIES - position`; else Deactivated (usable no more); `get_active_addresses_len()` — if `current_slot > last_extended_slot` all addresses usable, otherwise only addresses before `last_extended_slot_start_index` — **an address extended this slot cannot be looked up this slot**; deactivated tables report `LookupTableAccountNotFound` to callers (deliberately race-neutral error).
- **URL:** https://github.com/solana-program/address-lookup-table/blob/main/program/src/state.rs — **source code** (official Core BPF native program) — supports: same constants; program comment — "Address tables may only be used to lookup addresses that were extended before the current bank's slot"; meta layout and `ProgramState::{Uninitialized, LookupTable}`.
- **URL:** https://github.com/solana-program/address-lookup-table/blob/main/program/src/processor.rs — **source code** — supports: `CreateLookupTable` requires the `recent_slot` to be present in SlotHashes else `InvalidInstructionData` ("{} is not a recent slot"); table PDA = `[authority, recent_slot.to_le_bytes()]`; create allowed without authority signature post-SIMD (feature `FKAcEvNg...` relaxed signer check, mainnet epoch 577); `DeactivateLookupTable` sets `deactivation_slot = clock.slot`; deactivation is **permanent — no reactivation instruction exists**; "Deactivated tables cannot be extended" and "Deactivated tables cannot be frozen"; close path (`CloseLookupTable`) requires status Deactivated with `remaining_blocks` counted down via SlotHashes position.
- **URL:** https://github.com/solana-program/address-lookup-table/blob/main/program/src/instruction.rs — **source code** — supports: instruction enum = `CreateLookupTable { recent_slot, bump_seed }`, `FreezeLookupTable`, `ExtendLookupTable { new_addresses }`, `DeactivateLookupTable`, `CloseLookupTable`; create PDA seeds `[authority, recent_slot.to_le_bytes()]`; deactivation cool-down comment — "Deactivation requires a cool-down period to give in-flight transactions enough time to land... equivalent to the amount of time it takes for a slot to be removed from the slot hash list" (~512 slots).
- **URL:** https://github.com/anza-xyz/agave/blob/master/accounts-db/src/accounts.rs — **source code** — supports: `load_lookup_table_addresses_into` — table must be owned by the ALT program, be active (`get_active_addresses_len`), else `AddressLookupError::InvalidAccountData`/`LookupTableAccountNotFound`; loaded writable/readonly addresses appended to `LoadedAddresses` in lookup-table order.
- **URL:** https://github.com/anza-xyz/agave/blob/master/runtime/src/bank/address_lookup_table.rs — **source code** — supports: banking-stage loading via `AddressLoader::load_addresses`; returns `loaded_addresses` and the **minimum deactivation slot** across all referenced tables (used by the leader to avoid scheduling into tables about to deactivate).
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/cookbook/transactions/lookup-tables.mdx — **official docs (mirror)** — supports: one ALT stores up to 256 addresses; a transaction may reference multiple tables; runtime loads at most **64 accounts per transaction** regardless of table size; create/extend/fetch flows; "an address cannot be looked up in the same slot in which it was added" (docs example waits for the next confirmed slot); deactivation makes a table unusable, closable after cool-down; ALTs usable only by v0.
- **Signers cannot be looked up in an ALT:** supported by the versioned-transactions doc — "ALT-resolved accounts can only be writable or read-only (non-signer); they cannot be signers. The fee payer and every required signer remain in the message's static account list."
- **Reactivation:** none exists on-chain. Deactivation is one-way; to reuse an address set, create a fresh table (new PDA from a fresh `recent_slot`). Claims of "reactivate ALT" in third-party blogs are **not supported by the current program**. *Unverifiable/conflicting:* older blog posts describe reactivation; official source shows only Create/Freeze/Extend/Deactivate/Close.

*Authoritative: yes (program source + official docs).*

## 4. Compute budget; priority fees; getRecentPrioritizationFees

- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/core/fees/compute-budget.mdx — **official Solana docs (mirror)** — supports: per-instruction default **200,000 CU** (`DEFAULT_INSTRUCTION_COMPUTE_UNIT_LIMIT`, non-builtin) / **3,000 CU** (`MAX_BUILTIN_ALLOCATION_COMPUTE_UNIT_LIMIT`, builtin, SIMD-0170); transaction cap `MAX_COMPUTE_UNIT_LIMIT = 1,400,000`; default limit = `non_migratable_builtin×3,000 + not_migrated_builtin×3,000 + non_builtin×200,000 + migrated_builtin×200,000`, clamped to 1.4M; `SetComputeUnitLimit` clamps to u32 ≤ 1.4M; `SetComputeUnitPrice` accepts u64 (micro-lamports/CU); `SetLoadedAccountsDataSizeLimit` NonZeroU32 clamped to 64 MiB (`MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES`); `RequestHeapFrame` must be ≥32 KiB, ≤256 KiB, multiple of 1024; **one of each variant per transaction**, else `DuplicateInstruction`; compute-budget instructions cost 150 CU and an instruction slot; in **v1** transactions these instructions are no-ops (still 150 CU) — limits live in the message config and default to zero.
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/core/fees/fee-structure.mdx — **official docs (mirror)** — supports: `micro_lamport_fee = compute_unit_price × compute_unit_limit`; `prioritization_fee = ceil(micro_lamport_fee / 1_000_000)`; base fee = signatures (tx sigs + ed25519/secp256k1/secp256r1 precompile sigs) × 5,000 lamports; base fee 50% burn / 50% validator; priority fee 100% validator (SIMD-0096); priority fee charged on **requested** limit, not actual usage; formula source `compute-budget/src/compute_budget_limits.rs get_prioritization_fee`; `MICRO_LAMPORTS_PER_LAMPORT = 1_000_000`; v1 sets priority fee as absolute total lamports (no per-CU multiply, no rounding).
- **URL:** https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/rpc/http/getrecentprioritizationfees.mdx — **official RPC docs (mirror)** — supports: `getRecentPrioritizationFees` returns samples for up to **150 blocks**; optional array of writable-locked account addresses (**max 128 addresses** — unrelated to the tx account-lock limit); samples are micro-lamports per CU; implementation `get_recent_prioritization_fees` in agave rpc.
- **"20,000 CU per instruction" does not exist** in current protocol. Builtins default to 3,000. The 200k figure is correct for non-builtin instructions; 1.4M cap correct.
- **v0 vs v1 defaults:** omitting ComputeBudget instructions in legacy/v0 → 200k/non-builtin (sum, clamped 1.4M), 64 MiB data size, 32 KiB heap, 0 priority fee. Omitting config in **v1** → 0 CU limit and 0 loaded-accounts budget — the transaction **fails immediately** (`OutOfBudget` / `MaxLoadedAccountsDataSizeExceeded`). Any v1 tx built without explicit config is invalid in practice.
- **Heap:** `DEFAULT_HEAP_COST = 8 CUs` per 32 KiB page; `STACK_FRAME_SIZE = 4096`; max instruction stack depth 5 (9 with SIMD-0268); max SBF-to-SBF call depth 64.
- **Block limits (scheduler cost model):** `MAX_BLOCK_UNITS = 60,000,000` (SIMD-0286 proposes 100M); `MAX_WRITABLE_ACCOUNT_UNITS = 12,000,000`; `MAX_VOTE_UNITS = 36,000,000`; `MAX_BLOCK_ACCOUNTS_DATA_SIZE_DELTA = 100 MB`; cost components: signature cost 720 CUs/sig, write-lock 300 CUs, instruction-data 4 CUs/byte, ED25519 precompile 2,280 CUs, etc.
- **Scheduling:** priority = requested `compute_unit_price` (legacy/v0) or v1 absolute priority fee / requested CU; writable-account lock conflicts gate parallel execution.

*Authoritative: yes (official docs + agave/sdk source cross-refs).*

## 7. Token-2022 transfer fee extension

- **URL:** https://spl.solana.com/token-2022 — **official SPL docs** — supports: program id `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`; extension list includes **transfer fees**; extension data written after byte 165 of accounts / 82 of mints.
- **URL:** https://github.com/solana-program/token-2022/blob/main/interface/src/extension/transfer_fee/mod.rs — **source code** (official spl-token-2022-interface) — supports: `pub const MAX_FEE_BASIS_POINTS: u16 = 10_000;` `TransferFee { epoch: U64, maximum_fee: U64, transfer_fee_basis_points: U16 }`; `calculate_fee` uses ceil-division: `ceil(pre_fee_amount × bps / 10_000)`, **rounded UP**, then `cmp::min(raw_fee, maximum_fee)` — i.e. fees are ceil-rounded and capped by **`transfer_fee_maximum`** (field `maximum_fee`; SDK/API name `transfer_fee_maximum`); `calculate_pre_fee_amount` also ceil-divides; fees are effective only from `epoch` onward (scheduled fee changes); withheld fees are taken on transfer and stored on the **recipient** token account ("withheld"); harvest via `HarvestWithheldTokensToMint` / `WithdrawWithheldTokensFromMint` / `WithdrawWithheldTokensFromAccounts`; mint authority withdraws accumulated fees from the mint or from collected accounts.
- **URL:** https://github.com/solana-program/token-2022/blob/main/interface/src/extension/transfer_fee/instruction.rs — **source code** — supports: withdraw/harvest instruction set listed above; audit-relevant for completeness (fees are not auto-swept).
- **Withheld fees mechanics:** each transfer withholds `ceil(amount × bps / 10_000)` (≤ maximum_fee) from the transferred amount; the recipient receives `amount − fee`; the fee is held as "withheld" lamports-equivalent base units on the recipient's token account (tracked inside the account's extension data); frozen/locked until harvested/withdraw instructions run.
- **Ceil rounding:** confirmed — both directions (fee on transfer, pre-fee for target net amount) use ceil; an engine computing outputs must mirror ceil or it will under-transfer by up to 1 base unit per hop (and may round-trip-fail fees).
- **Transfer fee maximum:** per-transfer cap (`maximum_fee`) — distinct from bps rate; both can change per epoch.
- **Arbitrage-relevant pitfall:** Token-2022 mints with transfer fees make amount-out calculations path-dependent; the DLMM/Raydium/Orca integrations must net fees **before** comparing routes, and quotes must use ceil semantics.

*Authoritative: yes (official source + SPL docs).*

## Appendix A — Quick audit checklist keyed to the sections above

1. **Tx parser** must accept legacy, v0 and v1 envelopes; reject unknown version bytes; enforce 1232/1232/4096 size limits per format; check the 12-signature cap for v1; never assume v0-style ALTs exist in a v1 tx.
2. **ALT resolution** must mirror `get_active_addresses_len` (same-slot extensions invisible) and the SlotHashes cool-down (~512 slots); never treat a table's listed length as its lookup-usable length within the extension slot; verify tables are owned by the ALT program before use.
3. **Compute-budget handling:** for v1, read CU limit / loaded-accounts limit / heap / priority fee from TransactionConfigMask (absolute lamports for fee — no per-CU multiply); for legacy/v0, scan ComputeBudget instructions, enforce one-per-type, clamp to 1.4M / 64 MiB / [32 KiB, 256 KiB].
4. **Priority-fee estimation** must use `getRecentPrioritizationFees` (150-block cache, ≤128-address writable filter, micro-lamports/CU); v1 tx fees are invisible to ComputeBudget scans — derive from the message config instead.
5. **Jito integration:** never tip via an ALT-referenced tip account; tip inside the strategy transaction; `bundleOnly=true` for single-tx revert protection; track landing with `getBundleStatuses` / `getInflightBundleStatuses` (5-min window, max 5 ids); treat bundle submission as non-final until confirmed; do not send tips as standalone trailing txs (uncle bandit).
6. **DLMM adapter:** 70 bins per BinArray; PDA `["bin_array", lb_pair, i64 index]`; default bitmap −512…511, BinArrayBitmapExtension mandatory outside; `bin_id`/`active_id` are signed; swap direction derived from account ordering (X vs Y), not from any arg; fees in 1e9 precision; dynamic-fee decay uses `reduction_factor / 10_000`; bins outside default range without the extension account revert (`BitmapExtensionAccountIsNotProvided`).
7. **Token-2022:** apply ceil rounding and `transfer_fee_maximum` cap at every hop; re-read mint extension state per epoch; withheld fees are not spendable until harvested; `swap_v2` handles Token-2022, v1 `swap` does not; DLMM pools flag `token_mint_*_program_flag = 1` for Token-2022 mints.
8. **Kamino flash loans:** borrow and repay in the same top-level transaction; repay amount must equal borrow + exclusive-calculated fee (`amount × flash_loan_fee_sf`, U68F60 fixed point, min 1 lamport); never CPI a flash borrow/repay into another program; verify reserve's `flash_loan_fee_sf != u64::MAX` (loans disabled).
9. **Swap discriminators:** CPMM `swap_base_input`/`swap_base_output` (Anchor sighashes `143,190,90,218 / 55,217,98,86`), CLMM `swap`/`swap_v2`/`swap_router_base_in`, AMM v4 tags 9/11/16/17 (raw u8 tag + u64 LE), Whirlpool `swap` (Anchor sighash — same bytes as CLMM/DLMM `swap`). Dispatch on program id + discriminator pair, never discriminator alone.
10. **Account locks:** assume 64 writable+readonly locks per tx (legacy/v0/v1); 96 only if SIMD-0596 confirmed activated on the target cluster (`solana feature status` / agave feature-set); ALT-loaded addresses consume locks; design multi-hop routes to stay within the lock budget.

## Appendix B — Raw command/byte references

- 1232 = 1280 (IPv6 min MTU) − 40 (IPv6 header) − 8 (fragment header) — `PACKET_DATA_SIZE` (solana-sdk packet crate).
- v0 prefix byte `0x80`; v1 prefix byte `0x81`; legacy = high bit unset.
- Anchor sighash: `sha256("global:<ix_name>")[..8]` — e.g. `global:swap` → `f8 c6 9e 91 e1 75 87 c8`.
- ALT PDA: `[authority, recent_slot_le]`; BinArray PDA: `["bin_array", lb_pair, index_le_i64]`; bitmap extension PDA: `["bitmap", lb_pair]`; Kamino market-authority PDA: `[seeds::LENDING_MARKET_AUTH, lending_market]`.
- Kamino Fraction = U68F60 (60 fractional bits, u128 backing); `FRACTION_ONE = 2^60`.
- Token-2022 fee math: `fee = ceil(amount × bps / 10_000)` capped at `maximum_fee`; pre-fee inverse also ceil.
- agave `MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES = 67_108_864` (64 MiB); heap frame bounds 32,768–262,144 bytes, multiple of 1,024.
- Scheduler block limits: 60M CUs/block, 12M writable-account CUs, 100 MB accounts-data delta per block (SIMD-0286 proposes 100M CUs).
- Jito: max 5 tx/bundle; min tip 1,000 lamports; 8 tip accounts (section 5); `getRecentPrioritizationFees` cache ≤ 150 blocks.
